IT Ops Maturity Dashboard — User Manual

A project-level view of technology domain maturity, assessment progress and prioritized improvement opportunities. This guide covers each area of the application (Admin Setup, Assessment, Dashboard and Reports) in the order a new user encounters them.

4 sections Administrator · Assessor · Reviewer · Assessee Cycle-based assessments

Admin Setup

Admin Setup holds the standing data the rest of the application depends on: who may act in which role, which technology domains apply to which projects, the assessment cycles in use, and the staged Assessor / Reviewer / Assessee assignments for each project-domain pair.

The area is organized as four configuration steps, navigated using the step tabs at the top of the page. Each step is gated to its own role, and a Superuser holds all of them at once, making a Superuser the only user who can complete every step end to end. Everyone else sees only the step tabs their own role grants.

1 Configure RolesGrant employees the roles that govern access across the application. Superuser 2 Configure ScopeMap technology domains to the projects they apply to. Scope Administrator 3 Configure CycleDefine the assessment cycles and their open windows. Cycle Administrator 4 Configure AssessmentStage the three roles per domain, then create the assessments. Assessment Coordinator

Configure Roles Superuser only

Grants employees the functional roles (Scope Administrator, Cycle Administrator, Assessment Coordinator, and so on) that determine what they can see and do elsewhere in the application. Each row represents one employee's role grants; access can be scoped to a specific resource set, and a grant can be revoked without deleting its history.

Configure Scope Scope Administrator

Defines the Domain–Project Mapping: which technology domains (Linux, Windows, Cloud, Network and the rest) are in scope for each project. Use + New mapping or + Bulk map to add domains to a project, or Copy from another project… to reuse an existing configuration.

The read-only Project Resources column shows who currently holds an active allocation on the project. Where nobody is staffed, the application says so explicitly: that project cannot yet be given an Assessee in Configure Assessment.

Configure Cycle Cycle Administrator

Defines the assessment cycles, for example 2026 - FY27 or Q2 - RunOps, together with their open and close dates. Every assessment is created against one named cycle, and the cycle determines the window in which scoring is expected to complete.

Configure Assessment Assessment Coordinator

The final staging step. For each project-domain pair already defined in Configure Scope, select a cycle, then assign the Assessor, Reviewer and Assessee before selecting Create assessments. All three roles are mandatory for a domain to be created. If the Assessee candidate list comes up empty, return to Configure Scope and confirm the project is staffed.

Assessment

The Assessments area is where Assessors score technology domains, Reviewers approve or return that scoring, and Assessees track progress and respond to findings raised against their own project. What a user sees here is determined entirely by the role they hold on each assessment.

Assessor Scores the domain

The My Assessments tab lists every project/domain assignment in which the signed-in user is the Assessor, grouped by account and project, with running counts for Open, Returned for Revision, Pending for Review and Completed. Select Open assessment to begin scoring.

Within an assessment, each parameter is scored individually against a five-level maturity rubric, with space for notes and supporting evidence. Scores start unset rather than pre-filled, so nothing is reported as complete until the Assessor has deliberately entered a value.

Reviewer Approves or returns

The Needs Review tab lists every domain an Assessor has submitted and that is awaiting this Reviewer's decision. Each row stays flagged Action needed until it has been actioned.

Opening a review surfaces the Assessor's scores and supporting notes in full. From there the Reviewer either Approves the assessment, or Returns it for Revision with a comment explaining what must change. A returned assessment unlocks for the Assessor and moves back to In Progress.

Assessee Owns the findings

Assessees are the project resources a given assessment concerns. They receive a read-only view of every scored parameter for their domain, but hold a distinct authority in the workflow: only an Assessee may accept or reject an individual finding.

Any parameter scored below the maximum (below 5) is treated as a probable area of improvement and raised as a finding once the Reviewer has approved the assessment. If the Assessee no longer holds an active allocation on the project, the application prompts them to have that allocation extended in D365; while the prompt is showing, accepting or rejecting findings and submitting remediation updates are both disabled.

Findings lifecycle

Findings become actionable, presented with Accept and Reject controls, once the domain assessment has been approved by the Reviewer. From that point a finding follows one of two paths, and a rejected finding can return to the Assessee more than once.

How a finding reaches closure

Every finding starts Pending. It is closed either by the Assessee's own remediation update, or by the Assessor accepting the Assessee's rejection.

If the Assessee accepts

  • The finding moves to Accepted.
  • An Action Taken field opens on the same finding, where the Assessee records the remediation carried out and may attach evidence (PDF, JPG or PNG, up to 10 MB).
  • Submitting that update closes the finding immediately. No separate Assessor sign-off is required.
  • The domain assessment reads as fully Completed only once every finding it raised has reached Closed.

If the Assessee rejects

  • A dialog requires a mandatory comment setting out the basis for rejection; it cannot be submitted without one.
  • The finding moves to Rejected and reads "awaiting assessor's decision".
  • Responsibility passes to that assessment's own Assessor. The Assessee cannot reverse a rejection unilaterally once it is submitted.

Resolving a rejected finding Assessor decides

On the Assessor's own assessment screen, a rejected finding displays the Assessee's rejection comment together with two available actions.

  • Accept the rejection confirms the finding as invalid and moves it directly to Closed. Nothing further is required of the Assessee.
  • Dispute the rejection requires its own mandatory comment explaining why the finding should stand. The finding reopens to the Assessee, who then sees the dispute comment alongside their original rejection reason and must decide again.

This exchange continues until the finding is either accepted and closed through the Assessee's remediation update, or closed outright by the Assessor accepting the original rejection.

Dashboard

The Dashboard is the application's landing page, presenting an organization-wide view of technology domain maturity, assessment progress and the leading improvement opportunities across every account and project. Use the cycle, business unit, account and project selectors in the header to narrow the view.

Reports

Reports present a complete, filterable and exportable view of every assessment. Status filters (Open, In Progress, Completed, Suspended, Past Due, On Target, Draft > 15 days and Draft > 30 days) narrow the list in one click, and the search field locates a specific account, project, domain, Assessor or Reviewer. Download Excel exports the current filtered view.

Domain Assessment Report

One row per project-domain assessment, carrying the assigned Assessor, Reviewer and Assessee, current status, key dates, maturity percentage and level, and the finding counts behind them.

Parameter Detail Report

Drills down to one row per scored parameter within each domain assessment, for a granular view of individual scores and the findings they raised.
