1. Getting Started — Login, Navigation & User Management

Module Overview

Purpose: Provide secure authentication, role-based access control, and intuitive navigation for all users accessing the neurealm CSM Platform. Customer users authenticate via username/password, while neurealm employees authenticate using Microsoft 365.

Module ID MOD-001
Module Category Authentication & Navigation
Primary Users Customers (Username/Password) & neurealm Employees (Microsoft 365)
Dependencies None (Entry Point)

1.1 Functional Requirements

FR-AUTH-001 High
Customer Username/Password Authentication
System shall provide secure username and password authentication for customer users with password complexity requirements and session management. This authentication method is exclusively for customer access.
Acceptance Criteria:
  • Login form accepts username and password inputs for customer users
  • Passwords must meet complexity requirements: min 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special character
  • Passwords are case-sensitive and masked during entry
  • Invalid credentials display clear error message
  • Successful login redirects customer users to appropriate dashboard based on user role
  • Session expires after 60 minutes of inactivity
  • Customer accounts cannot use Microsoft 365 authentication
FR-AUTH-002 High
Microsoft 365 Authentication for neurealm Employees
System shall support Microsoft 365 authentication exclusively for neurealm employee users, allowing them to sign in using their corporate Microsoft 365 accounts. This authentication method is not available for customer users.
Acceptance Criteria:
  • "Sign in with Microsoft" button visible on login page for neurealm employees
  • Clicking button redirects to Microsoft 365 consent screen
  • Only neurealm corporate Microsoft 365 accounts are authorized
  • Upon authorization, neurealm employee is redirected back to platform and logged in
  • First-time Microsoft 365 login creates employee user profile automatically
  • OAuth errors are gracefully handled with user-friendly messages
  • Customer users cannot access Microsoft 365 authentication option
FR-AUTH-003 High
Password Reset Functionality
System shall provide self-service password reset capability via email verification with time-limited reset links.
Acceptance Criteria:
  • "Forgot Password?" link available on login page
  • User enters registered email address
  • System sends password reset email within 2-3 minutes
  • Reset link expires after 24 hours
  • Reset page validates new password against complexity requirements
  • Confirmation message displayed upon successful password reset
  • User can immediately log in with new password
FR-AUTH-004 Medium
Account Lockout Protection
System shall implement account lockout after multiple failed login attempts to prevent brute-force attacks.
Acceptance Criteria:
  • Account locks after 5 consecutive failed login attempts
  • Lockout duration is 30 minutes
  • Clear error message informs user of lockout status
  • Administrator can manually unlock accounts
  • Failed attempt counter resets upon successful login
FR-NAV-001 High
Global Navigation Menu
System shall provide consistent global navigation accessible from all pages with organized module groupings and search capability.
Acceptance Criteria:
  • Top navigation bar persistent across all pages
  • neurealm logo in top-left navigates to main dashboard
  • Main menu (☰) accessible from top navigation
  • Menu organized by logical module categories
  • Global search (🔍) available in top navigation
  • Notifications (🔔) icon displays pending alerts count
  • User profile menu provides access to settings and logout
FR-NAV-002 High
Customer Selector (Multi-Customer Access)
System shall provide customer selector dropdown for Neurealm employees managing multiple customer accounts.
Acceptance Criteria:
  • Customer selector visible in top navigation for users with multi-customer access
  • Dropdown lists all customers user has permission to access
  • Searchable dropdown for large customer lists
  • Selecting customer refreshes page with that customer's data
  • Current customer displayed prominently in selector
  • Last selected customer remembered in user session
FR-NAV-003 Medium
Collapsible Sidebar Navigation
System shall provide left sidebar navigation with collapsible functionality for quick module access.
Acceptance Criteria:
  • Sidebar displays major modules with icons and labels
  • Sidebar can be collapsed/expanded via toggle button
  • Keyboard shortcut Alt+/ toggles sidebar
  • Collapsed state shows icons only
  • Active module highlighted in sidebar
  • Sidebar state persists across sessions

1.4 Workflows & Process Flows

Standard Login Workflow

1
User
→ Navigates to platform URL
→ System displays login page with username/password fields and "Sign in with Microsoft" button
2
User
→ Enters username and password, clicks "Sign In"
→ System validates credentials against user database
3
System
→ Authenticates user and creates session
→ System redirects to appropriate dashboard based on user role (Customer Admin → Single Customer Dashboard; CSM → Multiple Customers Dashboard; Admin → Operational Dashboard)
4
System
→ Loads user preferences and permissions
→ Navigation menu displays modules accessible to user's role

Password Reset Workflow

1
User
→ Clicks "Forgot Password?" on login page
→ System displays password reset request page
2
User
→ Enters registered email address, clicks "Send Reset Link"
→ System validates email exists in database
3
System
→ Generates unique time-limited reset token (24-hour expiry)
→ System sends email with reset link to user's registered address
4
User
→ Clicks reset link in email
→ System validates token is valid and not expired, displays password reset form
5
User
→ Enters new password and confirmation, clicks "Reset Password"
→ System validates password meets requirements and both fields match, updates password in database, invalidates reset token
6
System
→ Displays success message
→ System redirects to login page after 3 seconds

Exception Paths

Failed Login Attempt
Condition: Invalid username or password entered
System Response: Display error message "Invalid username or password. Please try again." Increment failed attempt counter. If 5 failed attempts reached, lock account for 30 minutes and display lockout message.
User Action: Re-enter credentials or initiate password reset
Expired Password Reset Link
Condition: User clicks reset link after 24-hour expiry
System Response: Display error message "This password reset link has expired. Please request a new reset link."
User Action: Return to login page and initiate new password reset request

1.5 Business Rules

BR-AUTH-001
User sessions expire after 60 minutes of inactivity. Active sessions (with user interaction) remain valid for up to 8 hours before requiring re-authentication.
BR-AUTH-002
Password reset links are single-use and expire 24 hours after generation. Used or expired tokens cannot be reused even within the 24-hour window.
BR-AUTH-003
Account lockout occurs after 5 consecutive failed login attempts within any 30-minute window. Lockout duration is 30 minutes unless manually unlocked by administrator.
BR-AUTH-004
New passwords cannot be the same as the username and must not match any of the previous 3 passwords for that account (password history enforcement).
BR-NAV-001
Navigation menu displays only modules and features the user has permission to access based on their assigned role. Hidden modules cannot be accessed via direct URL entry.
BR-NAV-002
Customer selector dropdown is visible only to users with multi-customer access permissions (typically Neurealm employees). Customer admins always see only their own customer data.

1.8 Non-Functional Requirements

Performance

  • Login Response Time: Authentication process must complete within 2 seconds under normal load (95th percentile)
  • Page Load Time: Dashboard must render within 3 seconds of successful login
  • Concurrent Users: System must support minimum 500 concurrent authenticated users

Security

  • Password Storage: All passwords must be hashed using bcrypt with salt rounds ≥ 10
  • HTTPS Required: All authentication traffic must use TLS 1.2 or higher encryption
  • Session Tokens: Use cryptographically secure random tokens (min 256-bit entropy)
  • OWASP Compliance: Authentication system must comply with OWASP Top 10 security guidelines

Usability

  • Browser Support: Chrome 90+, Edge 90+, Firefox 88+, Safari 14+
  • Mobile Responsive: Login page and navigation must be fully responsive on tablets and smartphones
  • Error Messages: All error messages must be clear, actionable, and user-friendly (no technical jargon)

Accessibility

  • WCAG 2.1 Level AA: Login and navigation must meet WCAG 2.1 Level AA standards
  • Keyboard Navigation: All navigation elements must be keyboard accessible
  • Screen Reader Support: Form labels and navigation elements must have proper ARIA attributes

1.9 Assumptions & Constraints

Assumptions

  • Users have access to email for password reset functionality
  • Microsoft 365 authentication requires users to have existing Microsoft 365 accounts
  • Users have modern web browsers with JavaScript enabled
  • Network connectivity is stable for OAuth redirects

Constraints

  • Microsoft 365 authentication requires pre-configuration of Azure AD application registration and OAuth 2.0 client credentials
  • Password complexity requirements cannot be customized by individual customers
  • Session timeout values are system-wide and cannot be customized per user
  • Multi-factor authentication (MFA) is not currently implemented

Role-Based Dashboard Views

Functional Capabilities

FR-TASK-001 High
Task Planner (Calendar View)
System shall provide calendar-based task planner interface for viewing, creating, and managing tasks across different time periods.
Acceptance Criteria:
  • Calendar view modes: Month, Week, Day
  • Task creation: Title, Description, Assigned To, Due Date, Priority (High/Medium/Low), Category
  • Task categories: Audit, Finding Remediation, Customer Meeting, Milestone, General
  • Drag-and-drop task rescheduling in calendar
  • Task status: Not Started, In Progress, Completed, Overdue
  • Visual indicators: Color coding by priority, overdue highlighting
  • Filter tasks by: Assignee, Status, Priority, Category, Customer
FR-TASK-002 High
Task Creation from Context
System shall support automatic task creation from various module contexts with pre-populated details.
Acceptance Criteria:
  • From Audit Finding: Auto-create remediation task with finding details and default 30-day due date
  • From Audit Plan: Auto-create audit execution task with scheduled audit date
  • From BVD Idea: Create evaluation/review task when idea submitted
  • From Risk: Create mitigation action task linked to risk record
  • Manual task creation with all fields customizable
  • Task templates for common activities (QBR preparation, Monthly review, etc.)
FR-TASK-003 High
View Tasks & Events by Period
System shall provide list view of tasks and events filtered by time periods for focused execution and tracking.
Acceptance Criteria:
  • Period filters: This Week, This Month, This Quarter, Custom Date Range
  • Separate tabs: Tasks, Events, All
  • List displays: Task/Event Title, Due Date, Assignee, Status, Priority
  • Quick actions: Mark Complete, Reschedule, Edit, Delete
  • Sorting: By Due Date, Priority, Status, Assignee
  • Export task list to Excel/CSV
  • Bulk actions: Mark multiple tasks complete, reassign
FR-TASK-004 Medium
Event Management
System shall support event creation and management for scheduled activities distinct from action-oriented tasks.
Acceptance Criteria:
  • Event fields: Event Name, Description, Start Date/Time, End Date/Time, Location, Participants
  • Event types: Customer Meeting, QBR, Audit, Training, Milestone Review
  • Recurring events: Daily, Weekly, Monthly, Quarterly (with recurrence pattern)
  • Event reminders: 1 day before, 1 hour before, 15 minutes before
  • Participant invitation with email notification
  • Calendar integration option (iCal export)
  • Event attendance tracking (if applicable)
FR-TASK-005 Medium
Notifications & Reminders
System shall provide automated notifications for task assignments, due dates, and overdue items.
Acceptance Criteria:
  • Task assignment notification to assignee
  • Due date reminder: 3 days before, 1 day before, on due date
  • Overdue task alert: Daily until completed
  • Task completion notification to creator
  • Event reminder notifications
  • Notification channels: In-app notification center, Email (configurable)
  • Notification preferences: User can enable/disable specific notification types
FR-TASK-006 Low
Task Completion & Evidence
System shall support task completion workflow with optional evidence/notes attachment for audit trail.
Acceptance Criteria:
  • "Mark Complete" action with completion timestamp
  • Optional completion notes field (max 500 characters)
  • Evidence attachment for audit/compliance tasks (max 3 files, 5MB each)
  • Completion confirmation for high-priority tasks
  • Task history log: Created, Assigned, Reassigned, Completed
  • Reopening completed tasks if needed (with reason code)
